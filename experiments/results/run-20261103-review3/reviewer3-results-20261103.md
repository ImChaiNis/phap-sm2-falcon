# 审稿意见3：协议实测数据（2026-11-03独立复测）

本次重新构建当前生成的代码并运行真实 SM2/SM3、Falcon-512 运算、凭据分片重构和消息认证。下面的数据来自本轮新日志，不覆盖2026-11-02旧数据。

**实验平台：** Apple M3 MacBook Air（Mac15,13，4性能核+4能效核，16 GiB），macOS 26.6.2（25G83，aarch64），Oracle Java 23（23+37-2369），Kotlin 1.9.22，Bouncy Castle 1.86；每JVM `-Xms512m -Xmx512m -XX:+UseG1GC`。CPU频率、亲和性、功耗及热状态未受控。它是桌面协议仿真主机，不是具有新能源终端代表性的设备。没有把Ubuntu开发版本写成实际运行系统。

**运行规模：** 原14阶段在5个新JVM中各预热500次、测量1000次，共70,000条；额外4个凭据体验签阶段在另外5个新JVM中采用相同重复设计，共20,000条。所有JVM顺序运行，构建和功能试验与计时分开。90,000条计时均保留且检查通过；另有15×100=1500次受控功能试验。Maven 36项测试全部通过。

## 1. 真实编码尺寸与分片

单位为字节（B）。SM2签名采用固定64 B的 `r||s` 编码；Falcon-512采用666 B固定填充格式。`ell=256 B` 是每片凭据载荷上限，分片头另占44 B，因此满载分片的完整编码为300 B。以下长度由各fork真实签名二进制文件复核。

| 配置 | D_U | CA SM2签名 | CA Falcon签名 | Gamma_U | 应用消息签名 | ell | Nfrag | 各片凭据载荷 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| SM2-only | 128 | 64 | 0 | 200 | 64 | 256 | 1 | 200 |
| PHAP | 128 | 64 | 666 | 866 | 64 | 256 | 4 | 256, 256, 256, 98 |
| Falcon-message | 1025 | 64 | 666 | 1763 | 666 | 256 | 7 | 256, 256, 256, 256, 256, 256, 227 |
| Dual-message | 1025 | 64 | 666 | 1763 | 730 | 256 | 7 | 256, 256, 256, 256, 256, 256, 227 |

Dual-message的730 B是64 B SM2加666 B Falcon。Falcon-message仅指应用消息全部用Falcon签名；其凭据仍有双CA签名，并保留SM2端点公钥，因此不是全后量子PKI。两个Falcon应用配置的D额外包含897 B端点Falcon公钥。

凭据长度为 `4 + len(D) + 2 + len(CA-SM2) + 2 + len(CA-Falcon)`。128 B应用载荷时，四种消息记录依次为284/284/886/950 B；一次冷获取加首条消息为528/1326/2957/3021 B规范协议字节。另加测试适配器冷路径12/24/36/36 B、暖路径8 B framing；不含ACK、ready barrier、TCP/IP或MMS头。

## 2. 验证时间

表中为“中位数 / p95”，单位ms；每行5000条测量。新增凭据验签采用预先生成、已逐一验证的32个真实CA签名池；128 B用suite 2凭据体，1025 B用suite 3凭据体作为该尺寸类别的代表。它不是对每一suite分别隔离验签的结果。

## 3. 无缓存／有缓存的首次认证交付时间

同一JVM的发送与接收线程使用已建立的127.0.0.1 TCP连接（TCP_NODELAY）及共同的System.nanoTime时钟。起点为应用载荷就绪且尚未进行消息签名；终点为接收方验签、策略/时效/重放检查和认证交付完成、写ACK之前。

冷路径开始时没有端点凭据：先发消息，随后发送全部凭据分片，计时包含消息签名、消息编码、socket传输、分片解析/重构、摘要、CA签名验证、消息验证和交付。暖路径已经缓存且验证了仍有效凭据，只发送新消息；缓存预装不计入暖路径。冷仅指凭据缓存冷。两个路径均预置可信根和本地政策。

| 配置 | 冷：中位数 / p95 (ms) | 暖：中位数 / p95 (ms) | 冷 / 暖交付计数 |
|---|---:|---:|---:|
| SM2-only | 2.964167 / 3.338385 | 1.882980 / 2.586468 | 5000/5000；5000/5000 |
| PHAP | 2.959812 / 3.189412 | 1.811208 / 2.025450 | 5000/5000；5000/5000 |
| Falcon-message | 1.469500 / 1.571087 | 0.336083 / 0.483093 | 5000/5000；5000/5000 |
| Dual-message | 3.318417 / 3.887699 | 2.121520 / 2.322629 | 5000/5000；5000/5000 |

上表四配置采用独立实验比较适配器，生产PHAP解析器仍只接受version 1/suite 2。另直接运行生产Sender、Receiver、WireCodec（无socket）得：

| 生产PHAP核心 | 中位数 / p95 (ms) | 均值 [95% CI] (ms) |
|---|---:|---|
| cold | 2.975896 / 3.302654 | 3.017441 [2.922582, 3.112300] |
| warm | 1.805771 / 1.941177 | 1.820824 [1.768172, 1.873476] |

生产核心与比较适配器采用不同接收路径，不能相减得出纯网络开销。各路径排除CA签发/密钥生成、预先序列化凭据分片、连接建立、ACK返回、Android持久状态与KeyStore、TLS/MMS/物理链路，以及区块链提交/共识/终态、快照鉴别分发和撤销传播。
